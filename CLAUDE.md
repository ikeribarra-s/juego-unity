# Fluffterror — Claude Context

## Project Overview

Co-op comedic horror game for 1–8 players. Players enter a location, collect evidence, and extract.
Each character has a **special ability** and a **comic flaw** that interacts with other characters.

**Engine:** Unity 6000.4.0f1 | **Pipeline:** URP 17.4 | **Platform:** PC  
**Networking:** Unity Netcode for GameObjects (NGO) — Phase 4, not yet implemented  
**Input:** New Input System (InputActionAsset)

## Architecture

### ScriptableObject Architecture
Data lives in ScriptableObjects, not MonoBehaviours.

| Asset | Class | Purpose |
|---|---|---|
| `InputReader.asset` | `InputReader` | Wraps InputActionAsset, fires C# events |
| `BaseDefinition.asset` | `CharacterDefinition` | Base character type (MovementClass = Base) |
| `TrotinDefinition.asset` | `CharacterDefinition` | Trotín character type (MovementClass = Trotin) |
| `CharacterStats_Base.asset` | `CharacterStats` | Per-character movement/inventory/detection values |
| `TrotinStats.asset` | `CharacterStats` | Trotín-specific stat overrides |
| `EvidenceItem.asset` | `EvidenceItem` | Evidence definition (name, type, value) |
| `MissionConfig.asset` | `MissionConfig` | Mission parameters (evidence count formula) |

### Component Layout (every character)
```
GameObject
 ├── CharacterBase
 ├── CharacterController
 ├── CharacterMovement      (or TrotinMovement — auto-swapped by CharacterBase.OnValidate)
 ├── InventorySystem
 ├── InteractionSystem
 ├── PhysicsGrabber         (auto-added at runtime by CharacterBase.Awake if missing)
 │    └── GrabBeam (child GO with LineRenderer, created at runtime)
 ├── CharacterVitals        (auto-added by CharacterBase.Awake; IKillable death state)
 ├── TorchCarrier           (auto-added by CharacterBase.Awake; carries one Torch, held front-left & upright; G throws it)
 ├── CharacterAudio
 └── CameraRoot (child Transform, Y=1.6)
     └── Camera (child)
         ├── AudioListener
         ├── AudioReverbFilter
         ├── EnvironmentReverb
         └── CameraEffects
```

### Characters Base — `Assets/_Game/Characters/_Base/`
- **`CharacterDefinition.cs`** — ScriptableObject. Enum `MovementClass { Base, Trotin }`. Fields: `DisplayName`, `Movement`, `Stats`. Setting `Movement` in the Inspector triggers `OnValidate` → `SyncMovementComponent` which swaps the movement component automatically via `Undo.DestroyObjectImmediate` + `Undo.AddComponent`.
- **`CharacterStats.cs`** — Fields: `MoveSpeed=5`, `SprintMultiplier=1.8`, `Gravity=-20`, `JumpForce=6`, `CrouchSpeedMultiplier=0.5`, `LookSensitivity=0.15`, `InventorySlots=2`, `DetectionRadius=5`.
- **`CharacterBase.cs`** — RequireComponent: CharacterController, InventorySystem, InteractionSystem (NOT CharacterMovement — that is auto-managed). Serialized: `_definition (CharacterDefinition)`, `_input (InputReader)`, `_cameraRoot (Transform)`. Exposes: `Definition`, `Stats`, `Input`, `CameraRoot`, `Controller`, `Movement`, `Inventory`, `Interaction`, `Grabber`. Awake auto-adds `PhysicsGrabber` if the GameObject doesn't have one. Editor-only `OnValidate` calls `SyncMovementComponent` via `EditorApplication.delayCall`.
- **`CharacterMovement.cs`** — All fields `protected`, all methods `protected virtual`. `_cameraRoot` removed — reads `_character.CameraRoot` instead. Public properties: `IsSprinting`, `IsCrouching`. Update() → ApplyLook() → ApplyCrouch() → ApplyMovement(). Protected helper `ApplyGravityAndJump()` shared with subclasses. **Crouch** is hold-to-crouch (`CrouchEvent` true/false): `OnCrouch` only records `_crouchHeld` (and crouches on press); `ApplyCrouch` stands up **every frame** that the key is released and `CanStand()` is clear — so releasing under a low ceiling stands you up automatically once you leave it. `ApplyCrouch` lerps `_controller.height` toward target at `_crouchTransitionSpeed` **in lockstep with the camera Y**, recomputing `center = height*0.5` each frame so feet stay planted (no snap/pop). `CanStand()` SphereCast starts at the **top of the current capsule** (not mid-body) sweeping only the reclaimed gap — avoids the self-overlap that let players stand through low ceilings. Uses `SphereCastNonAlloc` with `QueryTriggerInteraction.Ignore` and skips the character's own colliders (`IsChildOf(transform)`). `_debugCrouch` toggle logs input/state/blocked events and draws the stand-up cast ray (green=clear, red=blocked).
- **`InventorySystem.cs`** — **Dormant**: evidence is now carried physically via PhysicsGrabber, nothing flows through here. Kept for Phase 2 abilities (Mochín). Exposes `Items` (always empty for now), `MaxSlots` from `_character.Stats.InventorySlots`, `IsFull`.
- **`InteractionSystem.cs`** — Raycast from camera forward (cyan debug ray). Finds Camera via `GetComponentInChildren` in Start. Subscribes to `InteractStartedEvent`. Stores `CurrentPrompt` for DebugHUD.
- **`TorchCarrier.cs`** — Auto-added by CharacterBase. Carries one `Torch`: parents it to the camera at `_holdLocalPosition`, disables its colliders, and every `LateUpdate` re-applies the rotation `yaw(character) * Euler(_holdLocalEuler) * Torch.UprightRotation` (`_keepUpright`, default on — stays vertical when the camera pitches). Subscribes to `DropItemEvent`: **G throws the torch** (`_throwSpeed=6` forward + `_throwUpward=1.5`) unless `PhysicsGrabber.IsHolding` or `PhysicsGrabber.LastReleaseFrame == Time.frameCount` (beam-held evidence keeps G priority; never throws both). Thrown torch ignores collisions with its thrower. Events `TorchPickedUp` / `TorchDropped` (any release) / `TorchThrown` (after `TorchDropped`, only for a G throw). **Hand hold**: `SetHandAnchor(hand, gripOffset, gripRotation)` (called by `TorchArmAnimator`) attaches the torch **rigidly** to the animated left hand every `LateUpdate` — rotation `hand.rotation * gripRotation * Euler(_holdLocalEuler) * UprightRotation`, position = fist centre + `_handHoldOffset` along the shaft (default y=0.19, so the fist holds the striped handle). Zero lag hand↔torch. A previously thrown torch has an interpolated Rigidbody: `TryCarry` sets `interpolation = None` while carried (restored on release) so it can't write a stale physics pose into the driven transform. Scales the torch by `_handHoldScale` (0.3 — the prefab is ~1.9 m tall; restored on release). `[DefaultExecutionOrder(100)]`: after the camera moved and after TorchArmAnimator's IK (order 50).
- **`TorchArmAnimator.cs`** — On the model child (Animator), `[DefaultExecutionOrder(50)]`. Blends the `LeftArm_Torch` layer 0→1 over `_blendTime` (0.25 s, smoothstep) on `TorchPickedUp`, back on `TorchDropped`; handles a torch already held at Start. Registers the `LeftHand` bone + grip (5-finger skeleton rig: `_gripOffset` (0, 0.092, 0.034) = centre of the finger loop in hand-bone space, `_gripEuler` (0, 0, 270) = hand→shaft frame, shaft +Y = hand +X, index side up) with `TorchCarrier`, only if the layer exists. **First-person viewmodel** (`_smoothLocalView`, local player only): each LateUpdate restores the last *animated* arm pose (re-cached only when the bones differ from what it wrote = a new RetroAnimationStepper step), expresses the animated hand in the **chest frame** (camera position + UpperChest rotation relative to its bind pose, captured in Awake) and SmoothDamps it there (`_handSmoothTime` 0.1 s, `_handRotationSharpness` 10) — in that frame the hand only moves with the arm animation, not with the head-look IK spine lean/twist (which lags the mouse) or the stepped body. It then places the smoothed hand in the **view frame** (camera yaw + pitch clamped to `_pitchFollowLimit` 30°, `_pitchFollow` 1) plus a small **`_viewOffset`** (0.052, -0.065, -0.035), and rotates it with the yaw + `_pitchTiltFollow` (0.5) × pitch so the torch stays nearly upright (2.7° level, 6–9.5° at ±15°). Analytic two-bone IK (elbow on the animated bend plane) with a **soft reach limit** (`_maxReach` 0.99 of the arm length, eased from 98 % of it) so the elbow never snaps straight. Blended by the layer weight. Measured (TestScene, 1.86 aspect): flame ≈ viewport (0.28, 0.51) level, (0.28, 0.53) at 15° up, (0.28, 0.49) at 15° down; whole lantern on screen from -15° to +15° (top ≤ 0.93, left edge ≥ 0.16); ±20° pitch sweep at 63°/s keeps the flame within y 0.45–0.60; arm extension ≤ 0.93; hand↔torch offset drift 0.001 mm; walking jitter 0.73 mm mean / 0.31 mm median (2nd difference in camera space). The lantern sits ~0.38 m from the eye (the skeleton's 0.67 m arm can't hold it further out without hitting its reach), so it reads large on screen; shrink `TorchCarrier._handHoldScale` if that's too much. Body stays stepped; only the left arm glides. Turn off for remote players (they see the plain animated pose, which already raises the lantern forward-left beside the head).

- **`PhysicsGrabber.cs`** — R.E.P.O.-style physics carry. Exposes `LastReleaseFrame` (frame of the last release/throw). `EvidencePickup.Interact` routes here via `interactor.Grabber.TryGrab(pickup)` (hold **E** to grip — release fires `InteractCanceledEvent` → `Release()`; **G** = `DropItemEvent` → throw with `_throwSpeed` impulse). FixedUpdate applies spring-damper acceleration toward `camera + forward × _holdDistance` (wall raycast pulls the hold point in front of geometry). Heavy items: `_liftFactor = clamp01(_maxLiftMass / mass)` weakens the grip and blends gravity back in, so they sag. Grip breaks beyond `_breakDistance`. Gravity disabled while held, restored on release. Beam: runtime LineRenderer child "GrabBeam", 12 segments, Perlin wobble, updated in LateUpdate; optional `_beamMaterial` (defaults to Sprites/Default). Events: `ItemGrabbed`, `ItemReleased` (consumed by CharacterAudio). Tunables: `_holdDistance=1.8`, `_springStrength=140`, `_damping=11`, `_angularDamping=6`, `_breakDistance=3.5`, `_maxLiftMass=8`, `_throwSpeed=8`.
- **`CameraEffects.cs`** — On the **Camera child** (not CameraRoot). Auto-discovers `CharacterBase` via `GetComponentInParent` in Awake. Head bob (sin wave on localPosition XY, scales with speed ratio). Z-axis tilt based on lateral velocity. Does not conflict with CharacterMovement because it lives one level lower in the hierarchy.

### Trotín — `Assets/_Game/Characters/Trotin/`
- **`TrotinMovement.cs`** — Inherits CharacterMovement. States: Moving / Sprinting / Flying.

  - Tunables: `_sprintMultiplier=3`, `_sprintDuration=5`, `_sprintCooldown=25`, `_flyingBurstMultiplier=2`, `_flyingDrag=1.5`, `_flyingUpward=2`, `_maxFlyingDuration=3`.

- **`DungeonGenerator.cs`** — Procedural BSP dungeon (walls + floors) **+ authored prop-dressing pass**. `[ContextMenu]` **Generate** / **Clear** (work outside Play mode; everything parented under a single `_dungeonRoot`, props under a `Decor` child). **Grid-based**: BSP `Split` → rooms placed in leaves → rooms + L-corridors carved into a `bool[,] _floor` (1 tile = 1 world unit). Geometry is **derived from the grid**: floor quads via greedy horizontal run-merge; a wall is placed only on a floor tile's edge where the neighbour is empty (collinear edges merged into runs). This makes corridor↔room openings appear automatically and prevents stray walls mid-corridor. Procedural `MeshFilter`+`MeshRenderer`+`MeshCollider` per piece. Default materials cached (`_runtimeFloorMat`/`_runtimeWallMat`).
  - **Room metadata**: each carved room is stored as `RoomInfo` (rect, center, area, `RoomType` enum: Empty/Storage/Bedroom/Library/Ritual/Extraction/Hall). `AssignRoomTypes` makes the largest room Extraction, others size-biased (big→Hall/Library/Ritual, small→Storage/Empty).
  - **Decoration** (`DecorateDungeon`, runs after floor/wall build, gated by `_decorate`): builds a `Cell[,]` occupancy grid (Wall/Corridor/RoomFree/Reserved/Filled) + `_roomIndex` ownership + `_doorways` (corridor tiles touching a room). `ReserveSkeleton` marks a center clearance + a straight route from every doorway to the room center as **Reserved** (stays walkable, off-limits to floor props) — this is what guarantees CharacterController navigation is never blocked. Floor props only land on `RoomFree` tiles (never corridors/reserved), wall fixtures only on wall-adjacent tiles.

Two-segment blend: `t ∈ [0,0.5]` = small room → hall; `t ∈ [0.5,1]` = hall → open. Smoothly drives `decayTime`, `reverbLevel`, `reflectionsLevel`, `diffusion`, `density` each frame. `reverbLevel` must be **positive** to be audible (range −10000 to +2000 mB; Unity default is −10000 = dry). **Acoustic zones (2026-11)**: `Audio/AcousticZone.cs` (enum `Acoustic` Small/Hall/Cave/Crypt/Sewer/Tower/Open; local-box volume, **no collider**, static registry) is added to every authored chunk prefab by `ChunkPrefabBuilder.AcousticFor` (by chunk name). Inside a zone the reverb target blends to that zone's preset (`_zonePresets`, serialized `Preset[]` in EnvironmentReverb, defaults in code; fades in over `_zoneBlendDistance` 1.5 m from the edge); elsewhere (and under the blend) **8** horizontal rays (cardinal + diagonal, triggers ignored), probe 0.2 s, `_smoothSpeed` 1.2.
- **Water (2026-11)** — `Environment/Chunks/WaterVolume.cs` (static registry on `VOL_Water*` in CH_SP_FloodedCrypt / CH_SP_SewerChannel, box top = water surface; `TryFind(feetPos)` with 0.12 m surface tolerance, `Nearest`, `RandomSurfacePoint`). `CharacterAudio` plays `_waterWalk/_waterSprint/_waterCrouch` steps while `WaterVolume.TryFind(transform.position)` and `_waterEnter` once on entering. `SoundscapeProfile.WaterLoop/WaterDrip/WaterRadius(16)/WaterDripInterval` → `SoundscapeController` 3D loop at the nearest volume's closest point + its own drip timer. SDs `SD_WaterWalk/SD_WaterSprint` (Footsteps), `SD_WaterSplash` (Character), `SD_Amb_WaterDrip`/`SD_BedWater` (Ambient).

## Key Design Decisions

- **CharacterController, not Rigidbody** for all characters except Trotín's flying state (simulated via velocity vector).
- **Protected virtual methods** on CharacterMovement so subclasses override only what they need.
- **`ApplyGravityAndJump()`** is a protected shared helper — TrotinMovement calls it explicitly at the top of its ApplyMovement override to avoid duplicating gravity code.
- **Evidence is carried physically (R.E.P.O.-style)**, not pocketed: `PhysicsGrabber` suspends the live rigidbody in front of the camera with a spring-damper force while the player holds E. The item keeps colliding with the world, can be stolen by gravity (grip breaks past `_breakDistance`), and fragile items shatter on hard impacts. `InventorySystem` is dormant until Phase 2 (Mochín).
- **ExtractionZone uses OnTriggerStay for evidence** because a beam-held item is already inside the trigger when the player releases it — OnTriggerEnter would never re-fire, so the drop would be missed.
- **CameraEffects on Camera child** (not CameraRoot) so bob/tilt offsets don't fight with pitch or crouch-Y managed by CharacterMovement on CameraRoot.
- **InputReader null guards**: Unity can call OnDisable before OnEnable during asset import; guard `if (_move == null) return` prevents NullReferenceException.
- **CharacterDefinition drives MovementClass**: assigning a `CharacterDefinition` SO in the Inspector auto-swaps the movement component (Base ↔ Trotin) via editor `OnValidate`. `_cameraRoot` lives on `CharacterBase` (not CharacterMovement) so it survives component swaps.
- **Dedicated `AudioSource` for footsteps**: `CharacterAudio` creates its own `AudioSource` in Awake instead of using the shared `SoundManager` pool. This prevents simultaneous overlapping steps from multiple pool slots firing at once.
- **`AudioReverbFilter` on the AudioListener (Camera)**: affects all sounds heard by the player globally. `reverbLevel` must be set to a **positive value** (e.g. +1000) to be audible — the Unity default of −10000 is completely dry.
- **`PixelateFeature` uses a static `Instance`**: `ScriptableRendererFeature.Create()` runs at app start and sets `Instance = this`. `HorrorPostFX` reads it in `Awake` and `OnValidate` — no serialized reference needed. This pattern works for any renderer feature that needs to be driven at runtime without a drag-and-drop reference.

## Known Bugs Fixed (do not reintroduce)

- `InputReader.OnDisable` NullReferenceException: guard `if (_move == null) return` at top, and `_actions?.FindActionMap(...)` null-conditional.
- Camera moving the capsule: CameraRoot must be a **child** of the character root, not at the root level. `_cameraRoot` field on CharacterBase must point to the CameraRoot child Transform.
- Trotín A/D rotation also rotated the camera (camera is a child): removed A/D entirely. Mouse-only steering.
- Crouch camera conflict: CharacterMovement sets CameraRoot.localPosition.y; CameraEffects sets Camera.localPosition. Different transforms, no conflict.
- Footsteps overlapping: `SoundManager` pool is round-robin — each step grabbed a fresh `AudioSource`, so rapid triggers stacked. Fixed by giving `CharacterAudio` its own dedicated `AudioSource` + a 0.18 s cooldown.
- `EnvironmentReverb` inaudible: `AudioReverbFilter.reverbLevel` defaults to −10000 (dry). Preset values must use **positive** mB for wet reverb (e.g. +1000 for a small room, +1500 for a hall). Setting it to −600 is still near-silent.
- `FindAnyObjectOfType` does not exist in Unity 2022.2+: correct API is `FindAnyObjectByType<T>()` (note "ByType", not "OfType").
- URP 17 (Unity 6) removed `ScriptableRenderPass.Execute(ScriptableRenderContext, ref RenderingData)` and `OnCameraSetup(CommandBuffer, ref RenderingData)`: must use `RecordRenderGraph(RenderGraph, ContextContainer)` with `AddRasterRenderPass` / `AddUnsafePass`. `RenderingData` no longer exists — use `frameData.Get<UniversalResourceData>()` and `frameData.Get<UniversalCameraData>()`.
- Crouch "not working": the Crouch action was only bound to `<Keyboard>/c` + gamepad East. Added `<Keyboard>/leftCtrl` as a second binding. If a key seems dead, check the actual binding in `InputSystem_Actions.inputactions` before touching the movement code — the logic was fine.
- Torch held flat: the Torch FBX is Z-up and the prefab root carries -90° X; `TorchCarrier.TryCarry` set `localRotation = Euler(_holdLocalEuler)` (zero) and wiped it (same with `Quaternion.identity` / `WallFacing(e)` in TestSceneBuilder / MultiSectionDungeonGenerator). Always compose with `Torch.UprightRotation` / the prefab's own rotation.
- Hand-held torch jitter ("ticks" on screen): the body animates at 24 fps via `RetroAnimationStepper` while the camera moves every frame (NeckFollowCamera SmoothDamp), so a hand-attached torch stair-stepped in camera space (walking: 2nd-difference ~31 mm/frame). Smoothing the *torch* fixed it but made it lag the hand (rejected). Final fix: smooth the *arm* — `TorchArmAnimator` smooths the hand in camera space + two-bone IK every frame, torch stays rigid on the hand (→ ~3.7 mm mean / 2.5 mm median, hand↔torch offset std ≈ 0). Don't glue camera-visible props to stepped bones; don't smooth the prop separately from the hand.
- Torch drifting up / elbow waving when looking around (5-finger skeleton): TorchArmAnimator smoothed the *body-anchored* animated hand in full camera space and added a big camera-space `_viewOffset` (0.25 m) to reach the framing. Pitching the camera moved the hand through the view (flame from viewport y 0.35 to 1.06 — off the top — during a ±20° sweep) and pushed the IK target past the short arm's reach: the solver hard-clamped at full extension (100 straight-arm frames, bend up to 178°), where the elbow position is infinitely sensitive, so it snapped/waved (elbow 2nd difference up to 55 mm/frame). The look-IK spine lean (lags the mouse) added to it. Fix: the animated pose itself frames the lantern (re-solved arm muscles, ~85 % reach), the hand is smoothed in the chest frame and re-placed in the view frame (viewmodel; spine lean cancels), small `_viewOffset`, and a soft reach limit. After: flame y 0.45–0.60 in the same sweep, extension ≤ 0.93, no straight-arm frames. Don't add big camera-space offsets to an IK target; keep it inside ~0.9 of the arm length.
- Torch missing from inventory / not throwable: it lives on `TorchCarrier`, not `InventorySystem`, and nothing was bound to `Drop()`. HUD now draws it; G throws it only when the grabber isn't holding/just released evidence (subscription order puts the grabber first, hence `LastReleaseFrame`).
- Crouch felt like a toggle: input was fine (Button action, performed/canceled → CrouchEvent true/false). `OnCrouch(false)` tried `CanStand()` **once** on release; if blocked (e.g. inside the TestScene crouch tunnel) the player stayed crouched forever until pressing again. Fix: track `_crouchHeld` and retry standing each frame in `ApplyCrouch`; the cast also ignores triggers and the character's own colliders (the TestScene `Character` has an extra 2.5 m `CapsuleCollider`).
- Land sound way too early: the scenes had `CharacterAudio._landSoundOffset = 1.2` s and the pre-fire estimates time-to-impact as `distance / |vy|` (no gravity), so it fired long before contact. Now 0 (exact touchdown) and unused when `AnimationAudioSync` drives landing on the JumpLand contact frame. Don't sync sounds to the Starter Assets clip events either — measure contacts with the analyser.
- Player skeleton dark / unlit by torches: `ToonOutline.shader` only compiled its additional-light loop under `#ifdef _ADDITIONAL_LIGHTS`, but the PC renderer is **Forward+**, where URP enables `_CLUSTER_LIGHT_LOOP` instead — so no point light ever reached the skeleton. It also added `albedo * _ShadowTint` as a constant (glow with no light) and only 0.4× ambient. Fix: `multi_compile _CLUSTER_LIGHT_LOOP`, loop under `_ADDITIONAL_LIGHTS || _ADDITIONAL_LIGHTS_VERTEX || USE_CLUSTER_LIGHT_LOOP` with an `InputData` (positionWS + normalizedScreenSpaceUV) for the cluster iterator, shadow tint as a fraction of each light, full SH ambient, fog. Any custom lit shader in this project needs the cluster keyword.
- Interior floors lit "from nowhere": (1) SampleScene had two directional lights — `Directional Light` (main, shadowed) and `DungeonLightingController`'s `Moon (managed)` (red, 0.3) — the second is an additional light, which URP never shadows, so it lit every roofed floor uniformly (TestScene had the same pair). (2) The torch prefab carried two unshadowed point lights at range 19.5 m (276 lights in the level), so light summed through walls into every room and Forward+ was over its visible-light cap. (3) The level had been generated before the upright-torch fix, so wall lanterns lay horizontally, half inside the wall. Fix: one directional per scene, one torch light (range 10, at the flame), `DynamicLightBudget` for shadows/culling, regenerated SampleScene (seed 30).
- Held torch blowing out the first-person view (white cage/hand, bright screen): the torch light sits inside the lantern a few cm from the cage and the fist — inverse-square gives them hundreds of times the light of a wall. Lowering the light would dim the world; fixed with Rendering Layers instead (`HeldTorchLighting`): the local viewmodel doesn't receive the held light, only a weak fill. Any custom lit shader must honour `_LIGHT_LAYERS` (`IsMatchingLightLayer`) for this to work.
- Local player's head cast no shadow: `FirstPersonBodyCull` hid the head by scaling the Humanoid Neck bone to 0.001, which removes the neck/head/jaw geometry from **every** pass, ShadowCaster included. Fix: keep the bones, hide by a baked per-vertex head/neck skin-weight mask (UV3) clipped only in the camera passes. Don't hide first-person body parts by scaling bones if they should still cast shadows. (A bounding sphere/capsule around the head was tried first and rejected: the stylised skull is ~0.45 m wide, so a shape big enough to cover it also clipped the shoulders/torch hand, and the neck stump still showed when looking down.)
- Crouch stand-up through ceilings / snap-pop: `CanStand()` SphereCast must start at the capsule **top** (Unity ignores colliders the cast already overlaps), and `ApplyCrouch` must lerp `height` + `center` together with the camera rather than snapping the collider instantly.
